# Результаты controlled C↔C+ — `wsfanout_ccplus_20260813r1`

## Итоговый вердикт

**`C=measurement_failed`; `C+=measurement_failed`; гипотеза локальной записи не оценивается.**

Обе руки штатно завершили зонд и свежий контрольный замер XRP с кодом `0`. Supervisor записал `supervisor_finished` в `2026-08-13T23:36:51Z`. Пороги `600/600` до прогрева, нулевых невосстановленных соединений, покрытия исходных выборок и `safety_abort=0` выполнены независимо для C и для C+. Пороги переподключения и волн **не ослаблялись** и нарушены у обеих рук.

C: OKX `74` и Bybit `66` незапланированных переподключений при лимите `≤1`; максимальная волна за `60 s` равна `36 / 31` при лимите `≤3`; на Bybit есть явная подпись `1011 keepalive ping timeout` (`3` закрытия). Контрольный замер C дал один обрыв OKX `1006` в минуту `22:29`.

C+: OKX `4` переподключения при лимите `≤1`; Bybit `0`; волна `2 / 0` проходит порог `≤3`; явного `1011` нет. Это всё равно `measurement_failed`.

По заранее объявленному правилу любая невалидная рука запрещает причинный вывод. Описательные `S/P p99`, одновременные превышения и метрики записи **не входят в матрицу C против C+**.

Это не Track `(B)`, не производственный parquet/publisher и не доказательство mounted-storage. Связанные записи: [live](latency-ws-fanout-ccplus-run-live.md), невалидная отдельная [C+](latency-ws-fanout-cplus-results.md), валидная [C `20260813r2`](latency-ws-fanout-bc-20260813r2-results.md), [панель A/B/C](latency-ws-fanout-abc-dashboard.md).

Те же пороги независимо для C и для C+. Пороги **не ослаблялись**.

## Правило решения (заранее) и исход

| Правило | Условие | Исход этой серии |
|---|---|---|
| Гипотеза **поддерживается** | C валидна и тихая **и** C+ валидна и хуже по reconnect/`1011` либо по `S/P p99` / dual / loop | не применимо |
| Гипотеза **ослаблена** | обе валидны и `C≈C+` по reconnect/`1011` и по `S/P p99` / dual / loop | не применимо |
| Гипотеза **не оценивается** | любая рука `measurement_failed` | **этот исход** |

**Факт:** в этом вечернем окне рука без записи дала шторм переподключений, а рука с записью — четыре OKX `1006` без `1011`. Это наблюдение о двух невалидных окнах, а не причинное сравнение.

**Не факт:** «запись безвредна», «запись помогает» и «запись виновата». Историческая отдельная C+ `20260813r1` в другом часе провалила Bybit `67` / волну `19` при том же пути слива. Валидная утренняя C `20260813r2` дала нулевые переподключения без записи. Окна разные, фон не контролировался, порядок один (`C → C+`).

Поэтому гипотеза «локальная запись — главный источник хвоста / обрывов» в этом запуске **не проверяема**.

## Что изменилось относительно валидной C `20260813r2`

Предназначенный профиль C **тот же**, не тихая переписка руки: тот же NEW VPS и collector PID `24505`, `N=300` с XRP, идентичный `universe_300.json` (file SHA `bd6faf22…`), `websockets 16.1`, `receive_mode=immediate_drain_unbounded_app_queue`, batch `30/3 s`, retry `10 s`, omitted `max_queue`, ping `20/20/2`, `3600/600/3000 s`, `write=null`. Runner C не передаёт `--write-*`; `git_head` на обеих копиях кода недоступен, но start-event knobs совпадают. Вечерний зонд умеет C+ (`write_policy` в start есть, значение `null`); поток `pickle` у этой C не стартовал.

Изменилось окно и контекст серии: `08:37–09:37Z` после B → `21:36–22:36Z` как первая рука `C→C+`. Compactor был на обеих границах утренней C и только на конце вечерней; backup в этих двух окнах C не работал. `fd_limit` процесса `1024` утром vs `8192` вечером; фактические FD `610/610`, лимит не исчерпан. Переподключения: утро `0/0`; вечер OKX `74` / Bybit `66`, все внешний `1006`, явный `1011` только `3` Bybit; ping вечером — один OKX `1006` в `22:29`, Bybit `0`. Pickle эту C не объясняет: записи не было. Отдельная C+ `19:38–20:38Z` провалилась в другом часе (Bybit `67`, `18×1011`) при включённой записи — это не причина вечерней C.

## Что явно не утверждается

- Не Track `(B)` и не основание открывать торговлю.
- `pickle` ≠ производственный parquet, publisher, spool или mount.
- Нулевые `dropped` не равны «запись не влияет на задержку».
- Описательные одновременные превышения `0/0` и `S/P p99` около единицы не делают руки валидными.
- То, что C+ здесь тише C, не ослабляет и не поддерживает гипотезу: пороги нарушены.
- Track `(B)` по-прежнему закрыт.

## Следующий шаг по лестнице

Проверка добавочной нагрузки локальной записи **не закрыта**: парная серия не дала двух валидных рук. Повторять ту же пару с теми же порогами имеет смысл только как новый контролируемый запуск, не как пересчёт этого. Пока новый запуск не запрошен, сырые артефакты на VPS сохраняются, production не трогать.
