# Панель доказательств A/B/C для WebSocket fan-out

> **Статус: пара B↔C в окне с `immediate_drain_unbounded_app_queue`
> классифицирована; H1 в этом автономном профиле не воспроизведена.** Валидны
> `r2 A`, `r2 B`, `Cdiag`, `BC r1 B` и обе руки `BC 20260813r2`. В
> `20260813r2` `B=valid` и `C=valid`, `S/P p99` около единицы, dual `0/0`.
> Полный разбор и расчёт non-XRP не доминирует относительно B. Исторические
> `r2 C` и `BC r1 C` остаются `measurement_failed` из-за reconnect/wave.
> Отдельная рука `C+` (`wsfanout_cplus_20260813r1`) тоже `measurement_failed`.
> Парная серия `C↔C+` (`wsfanout_ccplus_20260813r1`) завершена:
> обе руки `measurement_failed`, гипотеза локальной записи **не оценивается**;
> см. [результаты C↔C+](latency-ws-fanout-ccplus-results.md). Вердикт B↔C
> предварительный: один последовательный `B → C`, без повторённого
> случайного порядка.
>
> Это панель доказательств, а не финальный вердикт о производственном профиле
> и не основание открыть Track (B).

## Что проверялось

**Трек / блок:** `(D) collection reliability`; WebSocket-кадр → цикл
`asyncio` → минимальное отбрасывание либо полная обработка сообщений. В этих
опытах выключены bars, publisher, spool и запись parquet; production collector не
изменялся.

```text
OKX + Bybit WebSocket
        │
        ├─ A: только XRP-пара → базовый уровень сети и разбора/расчёта XRP
        ├─ B: 300 пар / 600 сокетов → non-XRP кадры дренируются и отбрасываются
        └─ C: 300 пар / 600 сокетов → полный разбор и расчёт всех потоков
                                      без долговременной записи
```

`A` измеряет базовый уровень. `B` проверяет вклад количества соединений,
подписок, файловых дескрипторов и входящего потока без обычной обработки
non-XRP. `C` должен был измерить добавочный вклад полной обработки поверх
`B`. Сравнение `B↔C` теперь есть в серии `wsfanout_bc_20260813r2` с общим
путём `immediate_drain_unbounded_app_queue`. Исторические C без этого пути
по-прежнему невалидны.

| Нога | S: p50 / p95 / p99 / max, ms | P: p50 / p95 / p99 / max, ms |

| OKX | 30 / 41 / 60 / 444 | 29 / 34 / 46 / 341 |

- Задержка цикла: p99 `5.020 ms`, max `37.623 ms`; превышения `>200 / >500 / >1000 ms`: `0 / 0 / 0`.
- Одновременные превышения доставки: `0 / 0` из 50 минут для `>500 / >1000 ms`.
- Ресурсы: CPU p50 / p95 / max `25.96 / 35.94 / 58.84%` одного core; RSS p50 / p95 / max `107.7 / 108.0 / 108.0 MiB`; FD p50 / p95 / max `610 / 610 / 610`; минимум доступной памяти `14.06 GiB`; load-1 p50 / p95 / max `1.071 / 1.604 / 1.924`.

Это подтверждает запас ресурсов только для точного автономного профиля
`Cdiag` на данном VPS. Это не проверка production collector, совместной
нагрузки или долговременного хранения.

## Почему `r2 C` невалидна

В steady-окне `r2 C` произошли 6 незапланированных reconnect на OKX и 94 на
Bybit. Все соединения затем восстановились, но это не отменяет заранее
объявленный критерий невалидности.

Форензика подтверждает 100 фактических завершений listener-итераций. У
исключений нет close code и reason; поэтому внешнюю причину нельзя назвать
ни ограничением биржи, ни локальной ошибкой. События Bybit образовывали
кластеры, включая 24 reconnect в минуту `00:39` и 34 в `00:40`. Подробности:
[форензика reconnect `C`](latency-ws-fanout-c-reconnect-forensics.md).

## Чем `Cdiag` отличается от `r2 C`

В `Cdiag` одновременно изменены три параметра:

- пакетирование подписок: 30 пар каждые 3 s вместо одной пары каждые 50 ms;
- интервал повторной попытки: 10 s вместо 3 s;
- очередь приёма: библиотечное значение по умолчанию вместо явного
  `max_queue=None`.

Нулевые reconnect в `Cdiag` совместимы с тем, что новая комбинация устранила
симптом `r2 C`. Они не доказывают, какой параметр сыграл роль, и не отделяют
изменение параметров от различий времени, внешнего пути до endpoint и фоновой
нагрузки.

## Статус матрицы причин

| Категория | Статус | Основание |
|---|---|---|
| Только соединения / FD / fan-out | `ослаблена` | Валидные `B r2`, `BC r1 B` и `BC 20260813r2 B` при 300 парах / 600 сокетах не показали тяжёлый хвост: S/P p99 около 1, dual `0/0`. Это не исключает другой профиль или окно. |
| Разбор и расчёт сообщений | `не доминирует в окне drain` | Валидный `BC 20260813r2`: C не хуже B, dual `0/0`, S/P p99 ≤2×. Исторические `r2 C` и `BC r1 C` не входят в эту матрицу. |
| Смешанная причина | `не подтверждена в этом окне` | Для смеси нужно «`B` хуже `A` и `C` хуже `B`»; здесь `B≈C` и обе тихие. |
| Фоновая нагрузка процесса / хоста | `не проверена` | Контролируемый парный опыт с фоном `off/on` не запускался. |

Статусы «ослаблена» не означают «опровергнута». Ни один из них не является
доказательством причинности или отсутствия риска в производственном профиле.

## Значение для будущего Track (B)

**Оснований открывать Track (B) нет.** Можно зафиксировать только
предварительный факт: автономный профиль `C` при `N=300`, 600 сокетах,
пакетировании `30/3 s`, retry `10 s`, библиотечном `max_queue` и пути
`immediate_drain_unbounded_app_queue` дал низкую задержку в одном 60-минутном
окне `20260813r2`. Тот же порядок величин ранее дал и `Cdiag`, но у него
одновременно изменены несколько knobs.

Это не безопасный производственный лимит: в опыте отсутствуют bars, persistence,
publisher и spool; фон не контролировался; один профиль и одно окно не
покрывают внешние режимы сети и бирж. Политика предела `N` не следует из
этого наблюдения.

## Минимальное оставшееся доказательство

Controlled `B↔C` при `N=300` с `immediate_drain_unbounded_app_queue`
**закрыт**: см.
[результаты `20260813r2`](latency-ws-fanout-bc-20260813r2-results.md).
Повторять ту же пару с теми же knobs не нужно.

Проверка локальной записи поверх валидной C **не закрыта**: отдельная
[`C+ 20260813r1`](latency-ws-fanout-cplus-results.md) и парная
[`C↔C+ 20260813r1`](latency-ws-fanout-ccplus-results.md) обе
`measurement_failed`; гипотеза записи не оценивается. Новый запуск не
стартовать, пока не запрошен.

Следующий ровно один опыт после явного запроса — повтор той же пары `C↔C+`
с теми же порогами либо другое производственное смещение (bars, совместная
нагрузка). Не открывать Track (B) и не выводить политику предела `N` из
автономных окон.
