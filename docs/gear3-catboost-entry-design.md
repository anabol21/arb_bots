# Gear 3 — CatBoost Entry: разметка и обучение (v0.1)

**Цель:** обучить нелинейную политику **входа**; выход Gear 2.2 остаётся фиксированным. Сравнить CatBoost с Gear 2.2 на одинаковом симуляторе, затем сопоставить с реальными сделками. Это исследовательская ветка, без изменений live-контура.

## 1. Данные и допущения

- Источник: 1 Гц `(ts_s, coin)` с признаками Gear 2.2/2.3 из immutable market bundle v5; время UTC. Архив: **10.08.2026 00:00 — 02.11.2026 15:55** (конец исключён), 210 853 200 строк, 51 монета в union (ICX исключён). Проверять `coin × day`, `usable`, версии producer и дыры; не считать union доступным на любую прошлую дату.
- Отдельно подключить **исторические funding settlements OKX/Bybit** и **апостериорную оценку среднего проскальзывания**: в market bundle v5 их нет. Версии/хеши источников фиксировать.
- Кандидат: `(t, coin, side)` на **общей сетке UTC 5 с**, только при валидном состоянии/котировке и доступности инструмента на момент `t`. Оценивать long/short отдельно. Не применять глобальный `K=1` при разметке. Область кандидатов (все валидные состояния или заранее заданный мягкий pre-gate) фиксировать до эксперимента; только исходные open-гейты позволят модели *фильтровать*, но не расширять входы Gear 2.2.

## 2. Вектор состояния и funding (v0.1)

Одна модель для обоих направлений: на каждом допустимом входе `(t, coin, side)` фиксировать **7 признаков**:

`spread_last`, `p50_1m`, `theta_1m` **от стороны входа**; `funding_okx_signed_pp`, `funding_bybit_signed_pp` — **доступные к `t` прогнозные ставки ближайшего settlement**, со знаком ожидаемого денежного результата по соответствующей ноге; `minutes_to_funding_okx`, `minutes_to_funding_bybit` — время до ближайшего settlement на каждой бирже. Ставки и spread/theta — в процентных пунктах; время — в минутах.

- Для **long OKX / short Bybit**: `funding_okx_signed_pp = −f_okx_pp`, `funding_bybit_signed_pp = +f_bybit_pp`; для **short OKX / long Bybit** знаки обратные (стандартная конвенция: положительный funding платит long). Расписания бирж учитывать **независимо**, не объединять платежи по общей временной сетке.
- **После settlement одной биржи** её `minutes_to_funding` переключается на время до **следующего** settlement, а `funding_*_signed_pp` — на **последний опубликованный и доступный к этому моменту прогноз** для следующего начисления. Другую биржу не обновлять принудительно. Если следующий прогноз ещё недоступен — пометить missing, не подставлять будущую реализованную ставку и не трактовать missing как ноль.
- Это обновление относится к **новым входным состояниям** после settlement: модель входа **не переоценивает открытую позицию**. Во время удержания бухгалтерия отдельно прибавляет фактический signed funding на каждом произошедшем settlement; будущие начисления и их ставки — **только таргет**, не ML-фичи.
- **Ablation M0:** три рыночных признака. **Основная модель M1:** все семь признаков. Опциональная поздняя проверка: добавить `funding_net_signed_pp = funding_okx_signed_pp + funding_bybit_signed_pp` (M2); в первую версию не включать.

Исторические прогнозы funding должны содержать `observed_at/available_at` и назначенный settlement. Присоединение признаков — строго *as-of* по доступному на `t` значению, не по окончательной ставке из архивной таблицы. Без такой истории M1 не считается воспроизводимой и не заменяется look-ahead-фичами.

## 3. Разметка

1. Для каждого кандидата гипотетически **открыть позицию в `t`**. Оценить начальный спред по `spread_last` с учётом стороны.
2. Найти **первый** выход на сетке `t+5, t+10, …, t+12 ч` по *неизменной* `decide_close()` Gear 2.2: `min_profit_pp=0.20`, `min_theta_close=0.05`, `usable`, `hold_open_overlap`; комиссия в условии выхода `fee_round_trip_pp=0.30`. **Funding и slippage не меняют момент выхода**, а учитываются в таргете.
3. Если выход не найден — **принудительное закрытие через 12 ч** по валидной цене; `exit_reason=timeout`. При недостатке будущего, локальной/глобальной дыре или невозможности оценить терминальную цену — `label_status=invalid/censored`, без фиктивного PnL. Не переносить сделки через разрыв **13.09 11:45 — 14.09 00:00 UTC**.
4. Рассчитать результат **тем же accounting engine**, что использован в funding-aware бэктесте, без MC: полный круг комиссий, среднее проскальзывание исполнения входа/выхода, **фактические начисления/списания funding внутри `[t, t_exit]` на каждой бирже** с правильным знаком и номиналом. Не вычитать расходы дважды.
5. Сохранить непрерывный таргет `y_net_pp` (дополнительно `y_net_usdt` при фиксированном номинале) и бинарный **`y_class = 1[y_net_pp > R]`**. `R` — заранее установленный *net*-порог классификации, **не** `min_profit_pp` политики выхода; стартовый контрольный вариант `R=0`.

**Выход разметчика:** `candidate_id, ts_entry, coin, side, X_at_entry, ts_exit, label_end_ts, exit_reason, hold_s, gross_pp, fees_pp, slip_pp, funding_pp, y_net_pp, y_class, label_status, episode_id, source_hashes`. Все `ts_exit`, `hold_s`, PnL и исходы — **запрещённые ML-признаки**. В `X_at_entry` допустимы только причинные признаки и опубликованная к `t` информация/прогноз funding; будущие реализованные ставки используются **только для таргета**.

## 4. Хронологические блоки и фолды

Равная календарная длительность для трёх **предтестовых** блоков (границы UTC, конец исключён):

| Блок | Интервал |
|---|---|
| B1 | 10.08 00:00:00 — 28.08 20:42:59 |
| B2 | 28.08 20:42:59 — 16.09 17:25:59 |
| B3 | 16.09 17:25:59 — 05.10 14:08:58 |
| **TEST, не трогать при выборе модели** | **05.10 14:08:58 — 28.10 08:04:15** |
| Reserve (доп. проверка) | 28.10 08:04:15 — 02.11 15:55:00 |

- **Fold 1:** train B1 → validate B2.
- **Fold 2:** train B1+B2 → validate B3.
- **Final fit:** выбранная конфигурация на B1+B2+B3 → единственная внешняя оценка на TEST.
- **Purge:** не включать в train наблюдения, чьи интервалы `[ts_entry, label_end_ts]` пересекают начало validation/test; безопасная упрощённая альтернатива — 12-часовой purge перед границей. Для подбора на validation не использовать исходы, уходящие за конец его блока. Делить **все монеты по единой временной границе**, не делать random split по строкам.

## 5. Обучение и проверка

- Первый эксперимент — **CatBoostClassifier** на `y_class`; непрерывный `y_net_pp` сохранить для анализа экономических ошибок и будущей регрессии. Небольшая глубина (2–4), ограниченный набор конфигураций; imputation/веса/препроцессинг считать по train. Не воспринимать соседние кандидаты одного эпизода как независимые: сохранять `episode_id`, смотреть результат по эпизодам и монетам.
- Две версии с одинаковыми настройками: **M0:** только `spread_last`, `p50_1m`, `theta_1m`; **M1 (основная):** те же три + четыре funding-признака из §2. Порог вероятности и гиперпараметры выбирать по двум validation replay, **не по TEST**; число деревьев для final fit определить до теста.
- На каждом validation и TEST запускать **полный последовательный replay с глобальным `K=1`**, тем же 5-секундным шагом, 12-часовым timeout, funding/fees/mean slippage и фиксированным выходом для CatBoost и Gear 2.2. Сравнить net-PnL, drawdown, число сделок, occupancy, funding, timeout и результат по монетам/эпизодам. AUC/PR-AUC и калибровка — вторичные метрики.
- На TEST три отчётные ветки: **CatBoost simulated / Gear 2.2 simulated / Gear 2.2 real fills**. Первые две — чистое A/B сравнение политики; реальные сделки — отдельный benchmark. Для оценки ошибки симулятора нужен **matched replay** по фактическим сигналам, а не вычитание PnL разных наборов сделок.

## 6. Гейты первого запуска

Перед обучением сохранить coverage report: кандидаты и валидные таргеты по `coin × day × side`, доли timeout/censored, баланс классов, распределения PnL и длительностей, переход producer 22.09 и изменение universe. Контрольные траектории разметчика должны совпасть с `decide_close()` и бухгалтерией существующего симулятора при одинаковых допущениях. Все изменения настроек — новой версией конфига; рабочие данные и live-код не менять.
