Статус: **принят 2026-08-16**. Не открывает реализацию склейки, приватные
каналы и маршрутизацию заявок.

Публичное ядро (`app/screaner_b_o.py` + этот профиль) — производственная
основа блок-схемы склейки. Полную автономность без человека и сторожа
сервера добирают уже в склейке: контур всё равно будут менять.

Сводка готовности трека сбора: [`d-track-ready-for-b.md`](d-track-ready-for-b.md).

## 3. Гейт задержки, который склейка имеет право закладывать

На этом профиле, на этом хосте, после прогрева не короче 10 минут:

| Правило | Число | Доказано |
|---------|-------|----------|
| объединённый 99-й процентиль задержки OKX / Bybit | **ниже 100 мс** | окно 1: 80 / 61; окно 2: 48 / 38 |
| отношение сборщик / контрольный опрос по `XRP` | **не выше 2.0** | окно 1: 1.74 / 1.75; окно 2: 1.30 / 1.52 |
| обе ноги выше 500 мс / выше 1000 мс | **не больше 1 минуты из 60** и **0** | оба окна: 1 / 0 |
| внеплановый обрыв / ошибка протокола / не восстановлено | **0** | `canary` 24 ч + оба окна `L1` |
| отказ публикации / очередь записи | **0** в окне | оба окна `L1` |
| `wave_60s` / плановый код `1006` | **не провал** | дыра лучше устаревшего спреда |

Не закладывать в склейку: 99-й процентиль задержки цикла событий и
посекундные процессор / память / дескрипторы — не измерялись.
Не закладывать хвост 11.08 (612 / 676 мс) как норму этого профиля.

## 4. Семантика данных для блок-схемы склейки

```text
публичные книги N=337 + бары OKX N=337
  → тики lean с явной дырой (не спред из устаревших ног)
  → /data/live → compact → удалённые тики
  → /data/bars  (скринер гира 1.5 читает отсюда)
```

Склейка должна:

- считать спреды из профиля `L1` при чтении;
- давать гиру 1.5 вход с локальных `bar_5m`;
- не торговать и не строить сигналы по тику с подавлением из-за возраста или поколения;
- трактовать плановый обрыв и неполное окно как честную дыру.

Склейка не должна в этой спецификации:

- требовать удалённую копию баров;
- открывать приватные каналы и заявки;
- менять приём котировок, разбор бирж и формулу спреда без отдельного разрешения.

## 5. Что готово как основа, а что нет

Готово как **публичная основа**: полный набор пар с записью, переподключение
версии 2, запрет устаревшего спреда, 99-й процентиль ниже 100 мс на двух окнах,
тики в резервной копии, бары на сервере.

Не готово и уходит в склейку:

- сторож по службе, журналу `runtime.log`, диску и тишине уплотнения;
- защита уплотнителя от нехватки памяти и переполнения диска;
- недели без присмотра;
- склейка в работе: бар → скринер 1.5 → слоты — это блок-схема склейки, не сборщик.
