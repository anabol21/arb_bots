## 1. Цель бота

**Цель.** Кросс-биржевой арбитраж на **редких аномальных** режимах: публичный сбор спредов → исторический скринер режима по волатильности/объёму → фиксированная модель сделки под гейтом скринера → (позже) политика размера и поиск параметров → (ещё позже) склейка с живым исполнением.

**Факт.** Публичный сбор всех 337 пар с записью на профиле `L1` держит 99-й процентиль доставки ниже 100 мс. Историческая метрика Top‑N уже канон: `soft short blend` `α≈0.75` ([`regime-metrics-v0.md`](regime-metrics-v0.md)).

**Разрешено.** Блок-схему рабочей стратегии можно специфицировать поверх `L1`.

**Запрещено.** Приватные каналы и заявки не пишем, пока нет утверждённой блок-схемы.

## 2. Операционная модель

```mermaid
flowchart TB
  GD["Вы + помощник GD"]
  OrchD["Оркестратор лид D"]
  OrchM["Оркестратор лид M"]
  OrchB["Оркестратор лид B"]
  AgentsD["Runtime Storage / Schema / Validation / Review"]
  AgentsM["Model Simulator / Integration Validator / Review / Schema"]
  AgentsB["только спецификация до открытия трека"]
  GD -->|"цели критерии приоритет"| OrchD
  GD -->|"цели критерии приоритет"| OrchM
  GD -->|"запрет реализации до гейта"| OrchB
  OrchD --> AgentsD
  OrchM --> AgentsM
  OrchB --> AgentsB
```

| Роль | Делает | Не делает |
|------|--------|-----------|
| **Вы + помощник (GD)** | Цель бота, приоритет недели, критерии готовности, открытие/закрытие трека, приёмка вердиктов | Реализацию кода вместо лида |
| **Оркестратор трека (лид)** | Одна задача → один реализующий агент → независимый гейт; отчёт в 8 блоках | Смену приоритетов GD; правку чужих файлов |
| **Специализированный агент** | Узкая работа в своей зоне владения | Открытие соседнего трека; «тихая» правка вне своей зоны |

Правила:

- Один активный чат = одна цель в одном треке. Чат GD — только дорожная карта и приёмка. Внутри (D) допустимо временное разделение на уплотнение/выгрузку и задержки при непересекающемся владении файлами.
- На этапе реализации один файл — один реализующий агент.
- Проверяющие агенты не чинят патч, который оценивают.
- `WebSocket ingest`, разбор бирж, расчёт спреда и торговая логика заморожены без явного разрешения.
- Локальный успех ≠ успех на сервере; сервер без доказательства устойчивого хранения ≠ готовность.
- Маршрутизация моделей субагентов (Task `model`): см. секцию **Preferred models** в [`.cursor/agents/orchestrator.md`](../.cursor/agents/orchestrator.md). Чат GD по умолчанию — `cursor-grok-4.6-high-fast`.

Соответствие треков фото ↔ репозиторий:

| Фото | Репозиторий | Лид | Агенты |
|------|-------------|-----|--------|
| **(D)** | Трек 1: сбор и хранение | Orchestrator | Runtime Storage, Schema Contract, Validation, Review Critic |
| **(M)** | Трек 2: историческая модель | Orchestrator | Model Simulator, Integration Validator, Review Critic; Schema при передаче данных |
| **(B)** | Трек 3: склейка / живое исполнение | Orchestrator как архитектор | Спецификация поверх `L1` разрешена; до утверждённой блок-схемы — **без реализации** |

## 3. Гейт перед треком (B)

Любая реализация приватного канала котировок, маршрутизации заявок или боевой блок-схемы **запрещена**, пока не закрыты все три пункта:

| # | Гейт | Критерий готовности | Статус |
|---|------|---------------------|--------|
| 1 | Природа высоких задержек входящих данных | На профиле `L1` измеримый 99-й процентиль доставки ниже 100 мс и отношение к контрольному опросу не выше 2.0; не «кажется нормально» | `done` — два независимых окна 16.08; полный контракт задержки цикла не закрыт. Профиль: [`b-public-l1-gate-config.md`](b-public-l1-gate-config.md), вердикт: [`latency-l1-verdict.md`](latency-l1-verdict.md) |
| 2 | Прототип стратегии на исторической симуляции в модельной ветви | Закрытый гир 1.0 + закрытый скринер гира 1.5 на истории; `baseline` 1.0 не сломан | `done` — гир 1.0 закрыт; гир 1.5 закрыт как скринер более волатильных монет (`soft short blend` `α≈0.75`, Top‑N / кластер); `regime_on` не критерий закрытия 1.5 ([`strategy-gears.md`](strategy-gears.md), [`regime-metrics-v0.md`](regime-metrics-v0.md)) |
| 3 | Автономный устойчивый публичный контур | Сборщик + уплотнение + выгрузка тиков устойчивы в масштабе дней; сторож и класс отпуска добирают в склейке | `done` для старта спецификации склейки — тики в резервной копии, бары на сервере, `canary` 24 ч. Не недели без присмотра. Сводка: [`d-track-ready-for-b.md`](d-track-ready-for-b.md) |

Блок-схему рабочей стратегии (B) можно рисовать в отдельном чате поверх профиля `L1`. Реализация приватных каналов и заявок по-прежнему запрещена до утверждённой блок-схемы.
