# Приватные параметры для бэктеста гира 2

Спецификация параметров для **M**, не клиент ордеров. Private-клиент в
сборщике по-прежнему запрещён. Живые/testnet опыты — чат B-private
([`b-private-unlock.md`](b-private-unlock.md)), не этот документ.

Лестница гиров: [`strategy-gears.md`](strategy-gears.md). Запрос публичных полей: [`data-format-model.md`](data-format-model.md). Источники parquet: [`model-data-sources.md`](model-data-sources.md).

Холст с тем же инвентарём: canvas `branch-b-private-params-mvp`.

## 1. Зачем этот документ

Скоро в **(B)** появится торговый контур, который **включает гир 2**: рынок всех монет → скринер более волатильных (гир **1.5**) → сделки фиксированной модели **1.0** в кластере, лимит `K`. Точный живой контур (сколько тикать, какой watchlist) позже следует из опытов **(D)**.

Чтобы **(M)** мог моделировать **реальный MVP** этой стратегии на истории, нужны величины, которых **нет** в публичном WS сборщика. Их нельзя выдумать из L1. Их можно:

- пометить как явные `HYPER` и начать каркас гира 2;
- один раз снять в sandbox (private WS / REST), **не** записывая в collector;
- отложить, пока D не даст публичный latency-профиль или пока B не выберет тип ордера.

Это не открытие live-клиента внутри M и не private в collector.

## 3. Публичное уже есть vs нельзя взять из книги

**Есть (collector + CSV):** L1 price/size; спреды при чтении; `okx_latency_ms` / freshness = доставка **книги**, не ордера; `bar_5m.volume`; score гира 1.5; `bybit_okx_universe.csv` (tick, lot, min, notional).

**Нет в публичном канале:** ACK / match / cancel; очередь vs видимый size; факт вашего fill; VIP/rebate; funding, списанный со счёта; equity/маржа; остаток rate-limit; hedge/unified; выбор private WS vs REST.

## 4. Инвентарь для честного гира 2 в M

Для каждого параметра: зачем врёт бэктест; как снять; ждать ли D.

### Задержка и fill — D не нужен

| Параметр | Без него | Замер | Ждать D |
|----------|----------|-------|---------|
| ACK ордера | Fill слишком рано | private WS: `t_ack − t_send`, p50/p95 по бирже | Нет |
| Match vs книга | Обе ноги «исполнены», одна в очереди | `fill_px`/`fill_ts` vs L1 parquet | Нет |
| Cancel ACK | Нет честного обрыва второй ноги | sandbox cancel; MVP = метка IOC | До контура B |
| Private WS vs REST | REST не 100 мс | Один канал в sandbox | Нет |
| OKX ≠ Bybit | Одна константа 100 мс | Два лога | Нет |
| Fill = public L1 | Оптимистичная цена | Сверка private fill с L1 | Нет |

### Комиссии / funding / rebate

| Параметр | Без него | Замер | Ждать D |
|----------|----------|-------|---------|
| Taker vs maker | Blend 7.5 bps **занижает** taker-taker | Публичная таблица + REST VIP | Нет |
| VIP / rebate | Счёт в обе стороны | Разовый REST | MVP = taker без rebate |
| Funding | Долгое удержание | Публичная история; private paid | После hold-time в гире 2 |
| 4 ноги / 1 номинал | Контракт 1.0 уже так | Поля fee в fill | Нет |

### Баланс / маржа / `K`

| Параметр | Без него | Замер | Ждать D |
|----------|----------|-------|---------|
| `K` слотов | Гир 2 не определён; это **HYPER стратегии**, не private API | Задать в симуляторе; B-v0 spec `K_live=1` | D ограничит **живой** K |
| Equity / маржа | Бесконечный капитал | REST; для `K=1` хватит метки notional | Нет |
| Max positions / leverage | `K` больше лимита | REST | При `K≤3` можно отложить |
| Unified / isolated | Общая маржа режет слоты | REST account mode | Контур B |
| Borrow | Лишний риск | Universe = USDT-SWAP; метка «без borrow» | Нет |

### Ордера / min / tick / lot

| Параметр | Без него | Замер | Ждать D |
|----------|----------|-------|---------|
| tick / lot / min | **Не private** — уже CSV; без округления мелкие монеты врут | `bybit_okx_universe.csv` | Нет — взять сейчас |
| IOC / limit / post-only | Путает maker/taker и очередь | Контур B; хвосты D влияют на выбор | Мягко; MVP = IOC/taker |
| Hedge vs one-way | Reject long/short | REST | Контур B |
| Reduce-only | Тихий reject close | sandbox | После sandbox |

### Rate-limit / reject / аккаунт

| Параметр | Без него | Замер | Ждать D |
|----------|----------|-------|---------|
| Burst ордеров | `K×2` биржи всегда проходят | sandbox; публичные лимиты как потолок | D: сколько живых тиков; при `K=1` слабо |
| Коды reject | 100% accept | Каталог sandbox, не collector | После sandbox |
| VIP tier | См. комиссии | REST one-shot | Можно ждать |
| API / IP | Не бэктест | — | Только B ops |
| ADL | Редкие хвосты | — | Дефер |

## 5. Минимальный MVP для старта M vs отложить

**Стартовать каркас гира 2 в M сейчас (помеченные `HYPER`):**

1. `Trade_Lat` **по бирже** — константы (100 мс или консервативнее); fill оптимистичный.
2. `fee_rate` **taker-taker** с публичной таблицы, не blend 7.5 bps; VIP — метка.
3. `K` и равный notional слота (пока `K=1` согласован с B-v0).
4. Округление tick/lot/min из universe CSV.
5. Fill = публичный L1 на `t+Trade_Lat`; без проскальзывания; `Check_volume=False` (или L1 size как оптимум).
6. Тип ордера: метка IOC/taker. Cancel / hedge / unified не моделировать.
7. Funding и rebate игнорировать, пока нет распределения hold-time.
8. Accept = 100%, кроме уже существующих гейтов 1.0.

**Sandbox, не D и не live-бот** (нужно до фразы «похоже на исполнение», не до каркаса): ACK/match p50/p95; fill vs L1; REST VIP.

**Ждать D:** p95 публичной книги для Gate A; `W_watch` / `N_ticks` / resubscribe; операционно допустимый живой `K`; влияние хвостов на limit vs IOC.

**Ждать live-гейт B-private:** routing, общая маржа, reject на реальном счёте.
Sandbox ACK — чат B-private на testnet, не collector.
