# Фиксация сборщика трека D как производственной верхней версии (2026-08-27)

**Вердикт:** после устранения остановки уплотнения из‑за исчерпания памяти в группе управления и суточной выдержки без перезапуска сборщика текущая производственная верхняя версия трека D зафиксирована коммитом `c626ffd` на ветке `main`.

## Что сломалось / в чём была ошибка

**Факт (симптом, 25 августа 2026).** Служба `spread-compactor.service` завершалась по исчерпанию памяти в группе управления (`MemoryMax=2500M`, `CONSTRAINT_MEMCG`), примерно каждые две минуты после начала простоя уплотнения.

**Факт (не причина).** Диск не был заполнен (~18 ГБ свободно). Резервное копирование тиков оставалось исправным: уплотнённые файлы в ожидании передачи = 0, очередь резервного копирования = 0.

**Факт (корневая причина).** Манифесты завершённых окон `/data/compacted/.state/spread_*.json` не выводились из эксплуатации после очистки `sent/` (~12 ч). Накопилось около 3825 JSON‑файлов с полными списками исходных путей; загрузка всех в оперативную память давала порядка 4,5 ГиБ RSS.

**Факт (последнее успешное уплотнение до простоя).** Окно до `2026-08-25T01:15Z`: `…T224000Z_…T224500Z`.

**Допущение.** Без усечения `.state` повторное повышение `MemoryMax` лишь отодвинуло бы ту же аварию; постоянным решением это не считается.

## Что изменено (код и эксплуатация)

### Код

**Факт.** В `app/storage/compactor.py` перед `_load_manifests` добавлен потоковый `_prune_expired_complete_states` — по одному JSON за раз:

1. только `status=complete`;
2. `window_end` старше `--retention-hours` (в производстве — 12);
3. не трогать, пока выход ещё лежит в `/data/compacted/` (ожидает передачи);
4. сначала удалять соответствующие файлы в `/data/live/archived/`;
5. JSON удалять только когда архивы по манифесту уже сняты.

События журнала: `compaction_state_pruned`, `compaction_state_prune_complete`. База `backup_manifest.sqlite3` этим путём **не** изменяется.

Тесты: `tests/test_compactor.py`. Подробности: [`docs/compactor-state-retention-20260825.md`](compactor-state-retention-20260825.md).

### Выкладка

**Факт.** На хост скопирован только `compactor.py` в `/root/spread_staging`. Сборщик **не** перезапускался (PID `902378`, `NRestarts=0` с 2026-08-20 13:08 UTC). Однократный запуск уплотнения: удалено 3793 манифеста, порядка 212 тыс. архивных файлов; уплотнение возобновилось.

### Не цели этой правки

- поднять `MemoryMax` как «лечение»;
- удалять строки sqlite резервного копирования вместе с JSON;
- менять дерево баров;
- трогать бота B;
- останавливать сборщик ради этой правки.

## Методология фиксации («зафиксировано»)

Порядок, которым эталон признан производственной верхней версией трека D:

1. **Назвать режим отказа до правки.** Исчерпание памяти в группе управления из‑за неограниченного роста `.state`, а не нехватка места на диске (`ENOSPC`).
2. **Минимальная правка + модульные тесты.** Не поднимать `MemoryMax` как постоянное решение; не останавливать сборщик.
3. **Выкладка в промежуточный каталог.** Однократный запуск с таблицей «до / после» (число JSON в `.state`, число удалённых манифестов и архивов, возобновление уплотнения).
4. **Выдержка более 24 ч (25→27 августа).** Критерии прохода:
   - сборщик с тем же PID;
   - усечение и уплотнение продолжаются;
   - число JSON в `.state` порядка часов удержания, а не тысяч;
   - очередь резервного копирования = 0;
   - пользователь подтвердил «зелёный» статус.
5. **Коммит только файлов трека D** как `c626ffd`, публикация на `main`, объявление в `docs/d-track-ready-for-b.md`. Не смешивать грязь трека B (бот) и трека модели.

**Явно:** обрыв SSH‑клиента на тяжёлой удалённой команде **не** является отказом сценариев сборщика и не опровергает суточную выдержку.
