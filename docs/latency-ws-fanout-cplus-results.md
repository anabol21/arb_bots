# Результаты C+ — `wsfanout_cplus_20260813r1`

## Итоговый вердикт

**`C+ = measurement_failed`. Причинное сравнение с валидной C `wsfanout_bc_20260813r2` не допускается.**

Рука штатно завершила зонд и свежий контрольный замер XRP с кодом `0`. Supervisor записал `supervisor_finished` в `2026-08-13T20:38:14Z`. Пороги `600/600`, нулевых невосстановленных соединений, покрытия исходных выборок и `safety_abort=0` выполнены. Порог незапланированных переподключений и волн нарушен: Bybit `67` переподключений при лимите `≤1`, максимальная волна за `60 s` равна `19` при лимите `≤3`. На Bybit есть явная подпись `1011 keepalive ping timeout` (`18` закрытий) и обрывы `1006` без кадра закрытия (`49` на Bybit, `1` на OKX).

Локальная пакетная запись `pickle` в этом окне **дошла до конца без потерь на очереди записи**: `dropped=0`, `backpressure_hits=0`, `write_errors=0`. Это факт о потоке записи, а не доказательство, что запись безвредна для задержки доставки или чтения keepalive. Описательные `S/P p99` и одновременные превышения ниже **не входят в матрицу C+ против C**.

Это не Track (B), не производственный путь parquet/publisher и не повтор валидной C. Связанные записи: [live](latency-ws-fanout-cplus-run-live.md), [валидная C](latency-ws-fanout-bc-20260813r2-results.md), [панель A/B/C](latency-ws-fanout-abc-dashboard.md), [форензика C](latency-ws-fanout-c-reconnect-forensics.md).

## Путь записи — наблюдаемые метрики

## Сравнение с валидной C и исторической невалидной C

| Сигнал | Валидная C `20260813r2` | C+ `20260813r1` | BC r1 C (невалидная) |
|---|---|---|---|
| `unplanned_reconnect` OKX / Bybit | `0 / 0` | `1 / 67` | `6 / 91` |
| Max wave 60 s | `0 / 0` | `1 / 19` | `4 / 25` |
| Явный `1011 keepalive ping timeout` | `0` | `18` Bybit | 22+ Bybit в форензике r1 |
| Validity | `valid` | `measurement_failed` | `measurement_failed` |
| Путь слива кадров | тот же `immediate_drain_unbounded_app_queue` | тот же | другой (без этого drain) |
| Локальная запись | нет | `pickle` вне пути слива | нет |

**Факт:** подпись обрывов Bybit с `1011` / `1006` в этом окне C+ **повторилась**, хотя путь слива кадров был тем же, что у валидной C.

**Факт:** валидная C без записи в другом окне (`08:37Z–09:37Z`) дала нулевые переподключения.

**Допущение, не доказательство:** рост CPU, RSS и `recv_pending_max` относительно валидной C совместим с добавочной нагрузкой записи, но не доказывает, что поток `pickle` сорвал чтение `pong`. Историческая невалидная C без записи давала похожую подпись. Окна времени разные, фон не контролировался, порядок не рандомизирован.

Поэтому гипотеза «локальная запись — главный источник хвоста / обрывов» в этом запуске **не проверяема**. Гипотеза «локальная запись безвредна» тоже **не подтверждена**.

## Что явно не утверждается

- Не Track (B) и не основание открывать торговлю.
- `pickle` ≠ производственный parquet, publisher, spool или mount.
- Нулевые `dropped` не равны «запись не влияет на задержку».
- Описательные одновременные превышения `0/0` и `S/P p99` около единицы на OKX не делают руку валидной.
- Одним окном с проваленными порогами переподключения нельзя закрыть вопрос производственных смещений (bars, совместная нагрузка, долговременная запись).

## Следующий шаг по лестнице

Проверка добавочной нагрузки локальной записи **не закрыта**: C+ не дала валидного окна. Повторять ту же руку с теми же порогами имеет смысл только как новый контролируемый запуск, не как пересчёт этого. Пока новый запуск не запрошен, сырые артефакты на VPS сохраняются, production не трогать.
