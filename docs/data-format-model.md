# Запрос данных для трека модели (гир 1–3)

Документ — **запрос со стороны модели**: какие поля могут понадобиться симулятору, скринеру режима и (позже) поиску параметров. Это **не** проект реализации сборщика. Лестница гиров: [`docs/strategy-gears.md`](strategy-gears.md).

Канон имён по возможности совпадает с уже собираемыми тиками и [`docs/storage-contract.md`](storage-contract.md). Список колонок тика в коде: [`app/schema/spread_event.py`](../app/schema/spread_event.py).

Сборщик — только **публичные** каналы. Задержки исполнения ордера с приватных каналов **не** в датасете (`Trade_Lat` снаружи).

---

## Принцип минимализма (целевой)

| Что | Где берём |
|-----|-----------|
| L1 bid/ask price + size | тики (обязательно) |
| `spread_long` / `spread_short` | **считаем при чтении** из L1; в новых данных **не нужны** как обязательные колонки |
| Амплитуда / OHLC mid | **считаем офлайн** из ряда mid по тикам L1; в барах **не** требуем |
| Объём свечи `5m` | **отдельный слой баров** (см. запрос ниже) |
| Перцентили, отношение к среднему | **в модели** по ряду баров объёма (+ mid из тиков) — для **гира 1.5** (скринер режима) |

Итого сверх L1-тиков модель просит: **объём пятиминутной свечи** (слой баров) начиная с **гира 1.5**. Спреды и амплитуду из L1 модель считает сама.

---

## Партиционирование тиков

`…/base_coin=<COIN>/event_date=<YYYY-MM-DD>/…parquet`  
В теле файла `event_date` нет (только партиция).

---

## Тики: обязательное для модели (ядро)

| Группа | Колонки | Зачем |
|--------|---------|--------|
| Время / id | `event_dt`, `event_local_ts_ms`, `base_coin`, `trigger` | сортировка, окна, `Trade_Lat` |
| Задержка | `okx_latency_ms`, `bybit_latency_ms` (+ `max_latency_ms` при наличии) | гейты, p95 |
| Свежесть | `okx_freshness_ms`, `bybit_freshness_ms` (+ `max_*`) | опциональный гейт |
| Сырые метки | `calc_local_ts_ms`, `okx_*_ts_ms`, `bybit_*_ts_ms` | аудит |
| L1 | `okx_bid_price/size`, `okx_ask_price/size`, `bybit_bid_price/size`, `bybit_ask_price/size` | спреды, volume gate, mid/амплитуда офлайн |

Имена объёмов на стакане — **`_size`**, не `_quantity`.

### Спреды (только формула при чтении)

- long = `(bybit_bid − okx_ask) / bybit_bid × 100`
- short = `(okx_bid − bybit_ask) / okx_bid × 100`

### `spread_long` / `spread_short` в файле

- **Сейчас (v1 заморожен):** колонки ещё могут присутствовать в writer — совместимость с гиром 1 и бэкапом.
- **Цель для модели / следующий контракт:** не требовать; не писать в новых пайплайнах, если L1 полный. Гир 1.0 на старых файлах со спредами остаётся валидным.

### Амплитуда

Считается из mid по тикам L1 (`mid = (bid+ask)/2` на опорной бирже), **не** хранится в тике и **не** входит в запрос баров.

## Legacy vs полный L1

| | Legacy | Полный L1 |
|--|--------|-----------|
| Признак | нет 8 book-колонок | есть price/size |
| Гир 2+ / volume gate на стакане | не использовать без оговорок | обязателен |
| Спреды в файле | часто есть | можно не писать (считать из L1) |

## Запрос: слой баров `5m` (объём свечи)

Для **скринера режима (гир 1.5)** модели нужен ряд **объёма пятиминутной свечи**. Амплитуду, перцентили, отношения к среднему модель считает сама из тиков L1 и/или из этого ряда `volume`. Дальше тот же ряд питает гейт входа гира 2 и (позже) политику размера в 2.5.

Семантика `volume` **не** задаётся здесь: её определяет ветка сборщика через подписку на канал баров. Этот документ только фиксирует поля, которые модель ожидает получить.

### Ожидаемый путь (логическое размещение)

```text
<BARS_ROOT>/bar_5m/base_coin=<COIN>/event_date=<YYYY-MM-DD>/….parquet
```

Не смешивать с тиковыми batch’ами.

### Минимальный набор полей бара

| Колонка | Смысл |
|---------|--------|
| `bar_start_ts_ms` | начало окна (включительно) |
| `bar_end_ts_ms` | конец (исключительно), +5 мин |
| `base_coin` | монета |
| `ref_exchange` | опорная биржа, канон: `okx` (при необходимости — отдельные поля по второй бирже) |
| `volume` | объём свечи за окно; смысл — у сборщика / канала баров |

`n_updates` **не** запрашиваем. Если понадобится контроль полноты — посчитать из тиков спреда офлайн.

Часовой ряд — офлайн из двенадцати пятиминуток при необходимости.

### Что считает модель (не входит в запрос к сборщику)

- `spread_*` из L1;
- амплитуда / OHLC mid из тиков за 5m или любой lookback;
- `volume / median(volume)`, перцентили `volume` за часы–дни;
- флаги / ранг аномального режима (**гир 1.5**); гейт входа для гира 2.

---

## Вне скоупа этого запроса

- Реализация сборщика, формулы и выбор канала для `volume`.
- Приватные каналы (latency ордера, аккаунт).
- L2+, funding, OI — без отдельного решения.
- Обязательные `spread_*` и `amplitude` в новых обязательных колонках.
- Перцентили и `n_updates` в слое баров.

## Версии

- **Тики v1** — текущий полный body (включая `spread_*` для совместимости) заморожен на время валидации бэкапа.
- **Цель модели** — опираться на L1; спреды не требовать.
- **Бары (запрос модели)** — поля пятиминутного объёма для гира **1.5** (`bar_*_ts`, `base_coin`, `ref_exchange`, `volume`); смысл `volume` — в ветке сборщика.
