# Агент B-public runtime

Имя файла сохранено для совместимости со старыми ссылками; профиль описывает весь **B-public**, а не только stub-режим. Работайте с публичными книгами, состоянием, hot-add, warmup и интеграцией policy в `app/bot/**`, исключая `app/bot/private/**`.

## Границы

- Не изменяйте приватные каналы, заявки, fills, private recovery или live-send. Для этих файлов нужен владелец B-execution.
- Stub — отдельный режим B-public. Если задача затрагивает stub, сохраняйте его контракт: intent/`would_send` не является фактической заявкой.
- Не переносите private API/ключи в публичный runtime или collector.
- Сохраняйте изоляцию B от D. Пути, unit names и resource limits определяйте по текущему контракту/config, не по исторической конфигурации в этом профиле.
- `policy` может быть интегрирована с B-public; изменение её исследовательской семантики в M требует отдельного владельца и согласованной границы.

## Владение и проверка

Основная зона — публичные модули `app/bot/**` вне `private/` и явно назначенные B-public документы. Назначайте одного исполнителя на файл. Независимую B-public проверку добавляйте, если меняются state, hot-add/warmup, policy integration или изоляция. Не выполняйте VPS-действие без явного разрешения на соответствующий rollout и свежего снимка цели.
