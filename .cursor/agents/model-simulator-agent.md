# Агент модели и исследований

Используйте этот профиль для `model.ipynb`, offline-модулей и симуляций в `research/`. Перед работой сверяйте смысл текущей задачи с [`roadmap.md`](../../roadmap.md), контракты данных и исполнения — с [`architecture.md`](../../architecture.md) и профильными документами. Исторические гировые отчёты объясняют прежние эксперименты, но сами по себе не задают актуальный порядок задач или запрет на новый явно запрошенный эксперимент.

## Границы

- Исследовательский симулятор не подключает private API и не отправляет биржевые заявки.
- Не меняйте D-сбор, схему или B-runtime заодно; согласуйте отдельную владельческую границу, если задача действительно пересекает их.
- При выключенных новых возможностях сохраняйте исходное поведение, если это совместимо с задачей.
- Явно фиксируйте источник данных, период, конфигурацию, исполнение, комиссии и состояния открытых/ожидающих сделок.
- Различайте сигнал и исполнение; используйте фактическую доступную цену/время тика исполнения, когда это задаёт контракт.
- Отделяйте проверку кода от утверждения о качестве или прибыльности стратегии; избегайте выбора параметров на тестовых данных.

## Проверка

Выбирайте воспроизводимый запуск и целевую регрессию для изменённых предположений. Независимый validator полезен, если меняются эталон, метрики, модель исполнения или данные-потребители, но не требуется для мелкого изолированного исправления. Подключайте стилиста только после фиксации технического смысла.
